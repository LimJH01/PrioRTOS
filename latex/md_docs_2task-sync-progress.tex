{\ttfamily kernel/ipcp.\+c}는 고정 ID mutex에 대해 IPCP를 처리한다. 초기화 시 {\ttfamily mutex\+\_\+configure(id, user\+\_\+slots)}로 사용 태스크 슬롯을 등록하면 기본 우선순위로 ceiling을 계산한다. ID와 사용자 목록은 스케줄러 시작 때 동결된다. lock은 요청 mutex의 free 여부와 system ceiling을 검사하며, 획득할 수 없는 태스크는 해당 mutex의 고정 waiter bitmap에서 대기한다. unlock은 보유 mutex의 ceiling으로 유효 우선순위를 재계산하고, system-\/ceiling 조건을 통과한 대기자에게 소유권을 넘긴 후 READY로 만든다. 세마포어는 IPCP와 별도 기능이다.

사용자 비트맵은 {\ttfamily g\+\_\+tcbs\mbox{[}\mbox{]}}의 슬롯 번호를 사용한다. 현재 {\ttfamily \doxylink{prio__rtos_8h_aefad3e5130121500bb004e7ca315e89e}{task\+\_\+create()}}는 기본 우선순위와 슬롯 번호를 같은 인수로 지정하므로, 예를 들어 슬롯 1과 2가 자원을 쓰면 초기화 코드에서 다음처럼 등록한다.

세마포어 카운트가 0일 때 {\ttfamily wait}는 현재 태스크를 {\ttfamily BLOCKED}로 바꾸고 ready bitmap에서 제외한다. {\ttfamily signal}은 대기자를 깨워 {\ttfamily READY}로 바꾸고 ready bitmap에 다시 넣는다. 따라서 스케줄러의 기존 고정 우선순위 선택 규칙이 다음 실행 태스크를 고른다.\hypertarget{md_docs_2task-sync-progress_autotoc_md110}{}\doxysection{\texorpdfstring{실제 문맥 전환 경로}{실제 문맥 전환 경로}}\label{md_docs_2task-sync-progress_autotoc_md110}
{\ttfamily \doxylink{kernel__internal_8h_a84cbe33479159518535a54988e337531}{sched\+\_\+schedule()}}은 다음 태스크를 선택하고 {\ttfamily g\+\_\+current\+\_\+tcb}를 갱신한다. 그 자체가 CPU 레지스터를 전환하는 코드는 아니다. 실제 저장/복원은 기존 \href{../kernel/context.S}{\texttt{ context.\+S}}의 trap entry/return 경로가 담당한다.

이 구현은 CLINT {\ttfamily MSIP}를 소프트웨어 재스케줄 요청으로 사용한다. 요청은 {\ttfamily MSIE}와 전역 {\ttfamily MIE}가 활성화된 시점에 trap entry로 전달되고, trap entry가 태스크 문맥을 저장한 뒤 {\ttfamily \doxylink{trap_8c_a854ac00fd47f7ec89466db38dda859fd}{trap\+\_\+handler()}}가 pending 비트를 지우고 스케줄러를 호출한다. 비동기 인터럽트이므로 {\ttfamily mepc}를 직접 증가시키지 않고, 인터럽트가 발생한 명령 위치로 복귀한다.\hypertarget{md_docs_2task-sync-progress_autotoc_md111}{}\doxysection{\texorpdfstring{확인한 결과}{확인한 결과}}\label{md_docs_2task-sync-progress_autotoc_md111}

QEMU 실행은 기능 확인이지 실기기 timing/\+WCET 검증은 아니다.\hypertarget{md_docs_2task-sync-progress_autotoc_md112}{}\doxysection{\texorpdfstring{아직 구현하지 않은 것과 주의점}{아직 구현하지 않은 것과 주의점}}\label{md_docs_2task-sync-progress_autotoc_md112}

\begin{DoxyEnumerate}
\item {\bfseries{Idle task가 없다.}} 모든 응용 태스크가 동시에 BLOCKED가 되면 ready bitmap이 0이 되어 현재 스케줄러가 panic한다. 이 A/B 데모에서는 하나의 토큰이 항상 진행 중이므로 정상 흐름에서 두 태스크가 동시에 기다리지는 않는다.
\item \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily \doxylink{prio__rtos_8h_ae92fe09f7ab93ec88821515714fb0926}{task\+\_\+yield()}}는 교대 API가 아니다.\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} 현재 태스크를 계속 READY로 두고 MSIP를 요청한다. 고정 우선순위 정책에서는 현재 태스크가 다시 선택될 수 있으며, 같은 우선순위 태스크 간 Round-\/\+Robin은 수행하지 않는다.
\item {\bfseries{IPCP 코드가 구현되었지만 아직 검증되지 않았다.}} 정적 설정, ceiling, 유효 우선순위 조정과 waiter handoff가 연결되어 있다. IPCP 요구사항별 자동 검증은 추가해야 한다.
\item {\bfseries{자동 테스트 및 정형 검증은 아직 없다.}} 현재 검증은 빌드와 QEMU 출력 확인에 한정된다.
\item {\bfseries{A/B 태스크 함수는 데모 코드다.}} 제품 사용 전에는 오류 정책, 동시성 경계, idle 동작 및 trap 오류 처리를 별도로 검증해야 한다.

\item IPCP의 설정 경계, system-\/ceiling 차단, nested lock, boost 복구 및 동순위 비선점 규칙을 자동 테스트한다.
