\hypertarget{md_docs_2requirements_autotoc_md102}{}\doxysection{\texorpdfstring{5. 검증 기준}{5. 검증 기준}}\label{md_docs_2requirements_autotoc_md102}

\begin{DoxyItemize}
\item 1차 QEMU 설정에서 RV32\+IMC ABI, {\ttfamily mtime} timebase 10 MHz 및 1 k\+Hz tick 주기를 확인한다. 실제 보드의 core clock/timebase는 별도 포팅 검증에서 확인한다.
\item 태스크 수와 우선순위 중복 제한, ready bitmap 비트 의미 및 최고 우선순위 선택 결과를 검증한다.
\item Mutex ceiling 승격·복원, 최대 4단계 중첩, 블로킹 금지 규칙 및 blocking bound를 검증한다.
\item 링크 결과와 소스 의존성을 검사해 부팅 완료 후 힙 할당/해제 호출이 없고, TCB와 태스크 스택이 정적 BSS에 배치되는지 확인한다.
\item CLZ 단일 명령·단일 사이클 성능은 RV32\+IMAC 빌드의 생성 코드 및 대상 하드웨어에서 별도로 확인한다. O(1) 복잡도만으로 사이클 상한이나 Hard Real-\/\+Time 보장을 주장하지 않는다.
\end{DoxyItemize}\hypertarget{md_docs_2requirements_autotoc_md103}{}\doxysection{\texorpdfstring{6. 현재 구현 기준\+: 부팅 및 트랩/패닉 동작}{6. 현재 구현 기준: 부팅 및 트랩/패닉 동작}}\label{md_docs_2requirements_autotoc_md103}
이 절은 목표 기능이 아니라 현재 소스 코드가 수행하는 동작을 명세한다. 적혀 있지 않은 기능은 구현된 것으로 간주하지 않는다.\hypertarget{md_docs_2requirements_autotoc_md104}{}\doxysubsection{\texorpdfstring{6.\+1 부팅 및 최초 태스크 실행}{6.1 부팅 및 최초 태스크 실행}}\label{md_docs_2requirements_autotoc_md104}

\begin{DoxyEnumerate}
\item 실행 환경이 {\ttfamily boot/startup.\+S}의 {\ttfamily \+\_\+start}로 제어를 넘긴다. 시작 코드 자체는 리셋 벡터 주소를 설정하지 않으므로, 실제 진입 주소는 보드 또는 로더 설정에 따른다.
\item {\ttfamily \+\_\+start}는 링커 심볼 {\ttfamily \+\_\+stack\+\_\+top}으로 {\ttfamily sp}를 설정하고, {\ttfamily \+\_\+\+\_\+bss\+\_\+start}부터 {\ttfamily \+\_\+\+\_\+bss\+\_\+end}까지 0으로 초기화한 뒤 {\ttfamily \doxylink{main_8c_a840291bc02cba5474a4cb46a9b9566fe}{main()}}을 호출한다. {\ttfamily mhartid} 검사, {\ttfamily gp} 초기화 및 {\ttfamily .data}의 LMA→\+VMA 복사는 수행하지 않는다. 현재 링커 스크립트는 {\ttfamily .data}를 RAM에 배치한다.
\item {\ttfamily \doxylink{main_8c_a840291bc02cba5474a4cb46a9b9566fe}{main()}}은 UART를 초기화하고 부팅 메시지를 출력한 뒤 {\ttfamily \doxylink{prio__rtos_8h_a7fd306118b826212968bc1f2d4045f61}{trap\+\_\+init()}}을 호출한다. {\ttfamily \doxylink{prio__rtos_8h_a7fd306118b826212968bc1f2d4045f61}{trap\+\_\+init()}}은 {\ttfamily trap\+\_\+entry} 주소를 {\ttfamily mtvec}에 기록하며 Vectored Mode를 설정하지 않으므로 Direct Mode로 동작한다.
\item {\ttfamily \doxylink{main_8c_a840291bc02cba5474a4cb46a9b9566fe}{main()}}은 CLINT 소프트웨어 인터럽트와 타이머를 초기화하고, 이어 {\ttfamily \doxylink{tasks_8c_a1d6e7fbd15bad66577c855e7d7166c1a}{tasks\+\_\+init()}}에서 응용 태스크 및 동기화 객체를 등록한다. 이 시점에 {\ttfamily mie}의 MSIE/\+MTIE 비트를 설정하지만, 전역 인터럽트 허용 비트 {\ttfamily mstatus.\+MIE}는 직접 켜지 않는다.
\item {\ttfamily \doxylink{prio__rtos_8h_a5d79d14e4f5972ce977309150daf4f06}{priortos\+\_\+start()}}는 Idle 태스크를 등록하고 IPCP 설정을 검증한 뒤 준비된 태스크 중 가장 높은 우선순위 태스크를 선택한다. 최초 문맥 복원 후 {\ttfamily mret}으로 해당 태스크 함수에 진입하며, 이때 저장된 {\ttfamily mstatus} 값에 따라 전역 인터럽트가 활성화된다.
\end{DoxyEnumerate}\hypertarget{md_docs_2requirements_autotoc_md105}{}\doxysubsection{\texorpdfstring{6.\+2 트랩 처리 및 패닉}{6.2 트랩 처리 및 패닉}}\label{md_docs_2requirements_autotoc_md105}

\begin{DoxyItemize}
\item 현재 {\ttfamily \doxylink{trap_8c_a854ac00fd47f7ec89466db38dda859fd}{trap\+\_\+handler()}}는 machine software interrupt ({\ttfamily mcause == 0x80000003})를 지우고 스케줄러를 호출한다. machine timer interrupt ({\ttfamily mcause == 0x80000007})에서는 다음 타이머를 예약하고 UART에 {\ttfamily .}을 출력한 뒤 스케줄러를 호출한다.
\item 그 외의 trap cause는 원인별 처리나 복구 없이 {\ttfamily \doxylink{trap_8c_a854ac00fd47f7ec89466db38dda859fd}{trap\+\_\+handler()}} 내부의 {\ttfamily wfi} 무한 루프에 진입한다. 이 경로는 {\ttfamily kernel\+\_\+panic()}을 호출하지 않으며 {\ttfamily mcause}, {\ttfamily mepc}, {\ttfamily mtval}을 출력하지 않는다. 따라서 불법 명령어, 주소 정렬 위반 및 접근 오류에 대해 별도 fail-\/stop panic 진단 정책을 제공하지 않는다.
\item 코드가 {\ttfamily kernel\+\_\+panic(msg)}를 직접 호출하면 {\ttfamily mstatus.\+MIE}를 0으로 설정하고, {\ttfamily msg}가 null이 아니면 {\ttfamily \mbox{[}KERNEL PANIC\mbox{]}} 접두사와 메시지를 UART로 출력한 뒤 {\ttfamily wfi} 무한 루프에 머문다. 개별 인터럽트 허용 비트({\ttfamily mie})를 지우거나 원인 CSR을 읽어 출력하지는 않는다.
\item 태스크 함수가 반환하면 {\ttfamily task\+\_\+exit\+\_\+trap()}의 {\ttfamily wfi} 무한 루프에 들어간다. 태스크 삭제나 종료 후 스케줄링은 수행하지 않는다. 
\end{DoxyItemize}
