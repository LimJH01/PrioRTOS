\hypertarget{md_docs_2function-conformance-v2_81_autotoc_md11}{}\doxysection{\texorpdfstring{구현 전반에서 명세와 다른 점}{구현 전반에서 명세와 다른 점}}\label{md_docs_2function-conformance-v2_81_autotoc_md11}

\begin{DoxyItemize}
\item v2.\+2 명세는 우선순위 0이 최고, 31이 최저이며 {\ttfamily Priority == Task Slot == Bit Index} 직접 매핑을 요구한다. 현재 구현은 이 우선순위 방향과 {\ttfamily slot = prio} 매핑을 따르고, 최하위 set bit를 De Bruijn LUT로 선택한다.
\item v2.\+2.\+1 명세의 {\ttfamily g\+\_\+ready\+\_\+bitmap}은 Running 태스크를 제외한 Ready 태스크 비트맵이어야 한다. 현재 {\ttfamily \doxylink{kernel__internal_8h_a84cbe33479159518535a54988e337531}{sched\+\_\+schedule()}}은 선점되는 현재 태스크를 READY로 바꾸면서 해당 슬롯 bit를 복구한다.
\item v2.\+2 명세는 {\ttfamily g\+\_\+prio\+\_\+to\+\_\+slot\mbox{[}32\mbox{]}}를 폐기했으므로, 기존 v2.\+1 대조표의 “priority-\/to-\/slot 매핑 미갱신”은 더 이상 핵심 불일치가 아니다. 현재 남은 문제는 IPCP 동적 priority와 직접 매핑 bitmap의 정합성, 그리고 Running 비트 처리다.
\item v2.\+2 명세는 {\ttfamily kernel/ipcp.\+c}의 동적 mutex 설정·waiter handoff 대신 {\ttfamily \doxylink{mutex_8c}{kernel/mutex.\+c}}의 정적 {\ttfamily mutex\+\_\+t}와 LIFO priority shadowing을 요구한다. 현재 구현은 {\ttfamily \doxylink{structTCB_a27fa4a29802a9290105f05aa4c837cac}{TCB\+\_\+t\+::held\+\_\+mutex}}를 유일한 소유권 장부로 사용하며, {\ttfamily kernel/ipcp.\+c}와 ID 기반 API는 제거되었다.
\item v2.\+2 명세의 1ms 타이머, {\ttfamily \doxylink{prio__rtos_8h_a2fe06f980a41193f64849956928c55ca}{timer\+\_\+tick\+\_\+step()}}, 64비트 system tick, 중첩 critical-\/section API는 연결되었다. sleep bitmap, timer overrun 재동기화, 대상 보드 WCET 측정은 별도 작업이다.
\item {\ttfamily TCB\+\_\+t}, {\ttfamily mutex\+\_\+t}, 함수 원형과 핵심 Mutex 경로는 현재 Master Spec의 정적 소유권 모델에 맞춰 동기화되었다. 타이머·sleep·\+QEMU 동작 검증은 별도 작업으로 남아 있다.
