# PrioRTOS 요구사항 카탈로그

이 문서는 PrioRTOS의 목표 하드웨어와 커널 요구사항을 영역별로 정리한다. 요구사항은 설계 및 검증의 기준이며, 문서에 명시된 것만으로 현재 구현이나 검증 완료를 의미하지는 않는다.

## 1. 플랫폼 및 시간 기준

| ID | 카탈로그 항목 | 요구사항 |
|---|---|---|
| `SYS-001` | 대상 플랫폼 | 대상은 RISC-V 32-bit `RV32IMAC`, SiFive Freedom E310 `FE310-G002` / HiFive1 Rev B로 한다. |
| `SYS-002` | 코어 클럭 | 기본 발진기 기준 코어 클럭은 16 MHz로 고정한다. |
| `TIME-001` | 시스템 타이머 | 시스템 타이머는 CLINT의 `mtime` / `mtimecmp`를 사용한다. |
| `TIME-002` | 시스템 tick | 시스템 tick은 100 Hz, 즉 10 ms 주기로 동작한다. `mtimecmp` 증가량은 실제 `mtime` timebase에 따라 계산한다. timebase가 16 MHz인 경우 한 tick은 160,000 count다. |
| `TIME-003` | 서브밀리초 타이밍 | 서브밀리초 정밀도가 필요한 태스크는 시스템 tick에 의존하지 않는다. 지터를 줄이기 위해 PWM 또는 타이머 하드웨어의 직접 인터럽트(ISR)로 트리거한다. |

## 2. 태스크 및 스케줄러

| ID | 카탈로그 항목 | 요구사항 |
|---|---|---|
| `TASK-001` | 고정 태스크 수 | 최대 태스크 수는 8개다. 태스크의 동적 생성 및 소멸은 지원하지 않는다. |
| `TASK-002` | 우선순위 | 우선순위 범위는 0–7이며, 숫자가 클수록 우선순위가 높다. 각 태스크는 서로 다른 우선순위를 사용해야 한다. 중복 우선순위는 허용하지 않는다. |
| `TASK-003` | Idle 태스크 | 우선순위 0은 Idle 태스크 전용이며 최하위 우선순위다. 나머지 우선순위 1–7은 응용 태스크에 사용한다. |
| `SCHED-001` | 준비 상태 비트맵 | 전체 태스크의 준비 상태는 단일 `uint8_t ready_bitmap`으로 관리한다. 비트 `k`는 우선순위 `k` 태스크를 나타내며, 해당 태스크가 준비 상태일 때 1이다. |
| `SCHED-002` | 최고 우선순위 선택 | 스케줄러는 준비 비트맵에서 가장 높은 우선순위의 set bit를 상수 시간에 선택한다. 지정된 탐색식은 `31 - __builtin_clz((uint32_t)ready_bitmap)`이며, 비트맵이 0인 경우의 처리는 별도로 안전하게 정의해야 한다. |
| `SCHED-003` | 스케줄링 정책 | 스케줄링은 선점형 고정 우선순위 방식이다. 준비된 태스크 중 가장 높은 유효 우선순위 태스크를 실행한다. 동일 우선순위 큐, FIFO 및 Round-Robin은 사용하지 않는다. |

> **ISA 확인 사항:** 표준 `RV32IMAC`에는 CLZ 명령이 포함되지 않는다. 따라서 단일 명령·단일 사이클 CLZ를 요구하는 빌드는 해당 명령을 제공하는 확장 또는 구현을 명시하고, 생성된 코드로 지원 여부를 확인해야 한다. 확인되지 않은 경우 CLZ 기반 단일 사이클 요구를 충족한 것으로 간주하지 않는다.

## 3. 동기화 및 IPCP

| ID | 카탈로그 항목 | 요구사항 |
|---|---|---|
| `IPC-001` | 정적 Mutex 및 Ceiling | 모든 Mutex는 정적으로 선언한다. 각 Mutex의 `ceiling_priority`는 해당 Mutex에 접근할 수 있는 태스크 중 가장 높은 우선순위로 사전에 정적으로 설정한다. |
| `IPC-002` | 즉시 우선순위 승격 | 태스크가 `mutex_lock()`에 진입하면 블로킹 없이 해당 Mutex의 `ceiling_priority`로 현재 태스크의 실행 우선순위를 즉시 승격한다. |
| `IPC-003` | 우선순위 복원 | `mutex_unlock()` 시 락 획득 직전의 우선순위 또는 중첩 락에 의해 저장된 직전 ceiling 우선순위로 즉시 복원한다. |
| `IPC-004` | 중첩 제한 | Mutex 락 중첩은 최대 2단계까지 허용한다. 세 번째 중첩은 허용하지 않는다. |
| `IPC-005` | Blocking bound | 태스크의 최악 블로킹 시간 `B_i`는 자신보다 낮은 우선순위 태스크가 실행하는 임계 구역 시간 중 최댓값 하나로 상한을 둔다. |

## 4. 메모리 및 결정론성

| ID | 카탈로그 항목 | 요구사항 |
|---|---|---|
| `MEM-001` | 정적 커널 메모리 | 모든 TCB와 태스크 스택은 BSS 영역의 정적 배열로 컴파일 시점에 고정 할당한다. |
| `MEM-002` | 힙 사용 금지 | 커널 부팅 완료 이후 `malloc()` 또는 `free()`를 호출하지 않는다. 커널 동작은 힙 동적 할당에 의존하지 않는다. |
| `DET-001` | 고정 자원 및 실행 경로 | 태스크 수, 우선순위 공간, 준비 비트맵 및 Mutex 중첩 한계는 고정한다. 스케줄러와 동기화 경로는 이 상한을 벗어난 동적 큐나 동적 메모리 할당을 사용하지 않는다. |

## 5. 검증 기준

- 타깃 설정에서 코어 클럭, `mtime` timebase 및 100 Hz tick 주기를 확인한다.
- 태스크 수와 우선순위 중복 제한, ready bitmap 비트 의미 및 최고 우선순위 선택 결과를 검증한다.
- Mutex ceiling 승격·복원, 최대 2단계 중첩, 블로킹 시간 상한을 검증한다.
- 링크 결과와 소스 의존성을 검사해 부팅 완료 후 힙 할당/해제 호출이 없고, TCB와 태스크 스택이 정적 BSS에 배치되는지 확인한다.
- CLZ 단일 명령·단일 사이클 성능은 RV32IMAC 빌드의 생성 코드 및 대상 하드웨어에서 별도로 확인한다. O(1) 복잡도만으로 사이클 상한이나 Hard Real-Time 보장을 주장하지 않는다.
